# M6.4 evaluation harness checkpoint

The benchmark runner exercises the same snapshot recommendation service as GradMatch. The development suite covers initial recommendations, follow-ups, clarification, evidence gaps, and shortfalls. It uses fictional profiles and the pinned 83-program catalog as of November 21, 2026. The fixed baseline, ReAct, and plan-and-replan receive the same scripted inputs in separate sessions.

## Reproduce

Start from the repository root with the project environment installed. Choose a fresh run directory for a new experiment.

```powershell
python -m scripts.run_benchmark --run-dir runs/m64-local --dry-run
python -m scripts.run_benchmark --run-dir runs/m64-local --resume --max-new-runs 9
python -m scripts.run_benchmark --run-dir runs/m64-local --resume
python -m scripts.summarize_results --runs runs/m64-local
python -m pytest -q tests/test_benchmark.py
```

The manifest pins the snapshot, task inputs, reference criteria, engine, and dependency versions. Each attempt saves the submission, output, and event log for every completed turn, followed by the grade and service metrics. A resumed run skips finished attempts. It records interruptions before starting a new attempt. Summary rates use the scheduled first attempts as the denominator, including rows with errors, interruptions or missing results. Latency and turn averages include only rows with those measurements, and the summary reports their sample counts.

Task inputs are in `eval/development/tasks.jsonl`. The grader reads `eval/development/oracles.jsonl` separately and checks specific outcomes, including cited evidence, recommendation eligibility, clarification, and unchanged profile fields. The missing-tuition case removes a reviewed tuition record and its program's official source excerpts before building the recommendation pool. Community records remain available as preliminary evidence.

## Formal suite authoring

The formal suite contains 210 tasks. The first 50 [profiles](../../eval/formal/tasks.jsonl) are complete initial submissions that can be assessed in one turn. The [oracles](../../eval/formal/oracles.jsonl) are stored separately and describe distinct anchors across tuition estimates and bounds, GPA calculation scopes, degree and coursework conditions, English scores and dates, GRE policies, intake, and goal evidence. The archived snapshot date is November 22, 2026, with 83 programs in the recommendation pool and 20 reviewed identities. [Formal snapshot configuration](../../config/eval_formal.json)

The optional oracle constraint checks compare the cited rule, program, status, and reason code. Tuition cases can also require exact numeric bounds. The existing exclusion and tier validators apply to the same output. Cases can pass with different preliminary shortlists when the required evidence checks hold.

```powershell
python -m scripts.run_benchmark --suite eval/formal/tasks.jsonl --oracle eval/formal/oracles.jsonl --config config/eval_formal.json --split formal --run-dir work/formal-local --dry-run
python -m scripts.run_benchmark --suite eval/formal/tasks.jsonl --oracle eval/formal/oracles.jsonl --config config/eval_formal.json --split formal --run-dir work/formal-local --resume --max-new-runs 630
```

The first rehearsal passed 144 of 150 executions. Two IELTS profiles caused all three strategies to ask for missing section scores. Adding the scores to the fictional inputs resolved those cases. Rehearsal manifests and results are retained separately under `work/formal-initial-rehearsal-01/`, `work/formal-initial-rehearsal-02/`, and `work/formal-initial-rehearsal-03/`.

The final rehearsal passed 50 of 50 cases in each strategy, for 150 of 150 runs and zero model requests. The 50 initial profiles are distinct, and their template families are disjoint from the development set.

### Follow-up tasks

The next 50 profiles add 45 two-turn tasks and five three-turn tasks. The follow-ups cover form edits, tuition-only chat updates, and an unchanged rerun. The oracle can verify the full expected applicant profile and its version on each assessment, including earlier turns. Selected cases also check when programs enter or leave the result. For example, case `f-follow-048` lowers the budget from $145,000 to $95,000 and restores it. MSAII goes from Lottery to excluded and back to Lottery. The Plan-and-replan trace records both profile revisions.

The first 300-run rehearsal passed 294 executions. Two references caused the six failures. USC's intake source applies to Fall 2027, which leaves the Summer intake unverified. The two references were corrected from the pinned evidence. The regrade reproduced every original result with the original rules, then passed all 300 saved executions under the corrected rules. Task inputs and engine hashes matched across grading passes. The initial run is in `work/formal-followup-rehearsal-01/`, and the separate regrade is in `work/formal-followup-regrade.json`. Paid requests were zero.

### Clarification tasks

The 40 clarification tasks use structured applicant inputs and isolated scripted replies. Thirty-six tasks have one clarification turn and four have two. They cover GPA scale and basis, tuition budget, intake, degree, GRE, English test date and subscores, goal, and major. A scripted `null` reply declares the requested field unavailable. The corresponding rule can stay pending while the assessment resumes in the same task.

The grader checks the exact fields requested on each specified turn, including duplicate or unrelated questions. Case `f-clarify-037` asks for an intake, then asks for an English report once the applicant selects Fall 2027. Case `f-clarify-040` keeps the supplied $50,000 budget while the applicant declares both GRE and English unavailable.

All three strategies passed 40 of 40 clarification fixtures in `work/formal-clarification-rehearsal-01/`. The extended grader also reproduced all 300 accepted assessments from the first two batches. The 17 focused regression tests passed, with an explicit check for unsolicited and duplicate questions. Paid requests were zero.

### Evidence-gap tasks

The 40 tasks cover 18 missing-source cases, eight stale-source cases, eight conflicting-source cases, and six existing snapshot limitations. Several cases use an explicit assessment date to test the day of a deadline or a passed schedule. Other cases test the applicable intake, attendance mode, or an English score floor with incomplete policy coverage. Every strategy uses the same scenario and assessment date.

The benchmark applies evidence changes in memory before building the recommendation pool. Its projections redact excerpts and remove affected current bindings, including tuition that depends on withheld credit counts. Independent facts keep their source bindings. Synthetic stale records and conflicting claims remain marked and are ineligible as official verification. Case `f-gap-027` provides competing UW credit counts. The result leaves tuition pending and verifies the applicable GPA requirement from a separate source. Case `f-gap-013` keeps the UCSD duplicate-degree policy in scope while its separate application checklist is unavailable.

All three strategies passed all 40 cases in `work/formal-evidence-gap-rehearsal-02/`. The 19 focused regression tests passed. The runner used snapshot fixtures with network access blocked and zero paid requests.

### Shortfall tasks

The final 30 cases distinguish verified constraint failures from unresolved eligibility. They cover hard budget and GPA floors, tuition bounds, program-specific English and GRE rules, credential timing, goal fit, and deadline scope. The oracles verify the exact number of validated recommendations in each tier. The displayed shortfall must agree with the count and include a reason.

Case `f-short-001` keeps an explicit zero-dollar cap in force. It excludes UW PMP based on its verified price while leaving NC State pending because its published tuition ceiling cannot establish the minimum charge. Case `f-short-023` uses a strong fictional 4.0-GPA profile and requires one supported Lottery recommendation with explicit Reach, Target, and Safer shortfalls.

### Model-backed main runner

The main evaluation runner supports `--live-model` for the configured provider while the application reads its pinned snapshot. The same task inputs, oracle isolation, and first-attempt grading apply to both modes. A paid run requires an explicit cumulative request cap and has a separate cap per task session. The run stores the model name, configuration, and pricing snapshot without writing the credential.

The request ledger reserves a slot before transport and preserves it across interruptions and resumes. A request with unconfirmed provider usage still consumes a slot. The summary reports known costs and token sample sizes, and preserves missing costs as unknown. It includes scheduled failures, interruptions, and unrun cases in the task-success denominator. Retry records remain separate from the first-attempt metrics.

The development pilot schedules two cases across all three strategies. The dry run creates the manifest without making a request.

```powershell
python -m scripts.run_benchmark --config config/eval_formal.json --task-ids dev01 dev04 --live-model --max-model-requests 26 --max-requests-per-task 10 --run-dir work/model-benchmark-pilot-01 --dry-run
```

To start the planned pilot after approving the paid requests, use the same arguments and replace `--dry-run` with `--resume`. The pilot results are separate from the formal 210-task benchmark. The formal schedule also preselects six audit tasks per category, for 30 tasks locked before model outputs are collected.

### First model-backed development pilot

On November 22, 2026, `gpt-5.4-mini-2026-03-17` ran `dev01` and `dev04` under each strategy. All six first attempts are recorded. The run received 20 provider responses, with 349,392 input tokens and 13,064 output tokens. The estimated cost was USD 0.22250880 using the pinned prices.

| Strategy | Passed | Avg. turns | Avg. service time | p95 service time | Avg. tokens | Requests |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Fixed baseline | 2/2 | 1.5 | 5.54 s | 6.47 s | 42,538 | 3 |
| ReAct | 1/2 | 1.5 | 18.15 s | 20.11 s | 60,926 | 9 |
| Plan-and-replan | 2/2 | 1.5 | 10.51 s | 15.41 s | 77,764 | 8 |

In `dev04`, ReAct saved the new $50,000 budget at profile version 2, then received two structured objects from one provider response. Both named the same tool and supplied byte-identical serialized arguments. Their summaries differed. The previous decoder treated the full objects as conflicting, rejected the action, and returned an error before recomputing exclusions. The fixed baseline and Plan-and-replan both verified that the lower budget excluded CMU MSAII. On its first turn, Plan-and-replan also revised a failed draft after an invalid preliminary program ID, then completed the requested profile update in a separate revision.

The updated decoder validates each repeated Action object and normalizes copies only when the tool and serialized arguments match. Other structured response types still require identical copies. An offline replay of the recorded ReAct response executed the normalized action once, then used fixture decisions to finish the turn and verify the MSAII exclusion. The pilot's original 5/6 result stays recorded.

The manifest, original traces, provider ledger, and summary are in `work/model-benchmark-pilot-01/`. The separate replay result is in its `react-normalization-replay/` subdirectory.

### ReAct budget retest

A fresh ReAct session passed both turns of `dev04` on November 22, 2026. CMU MSAII held a supported Lottery label at $140,000. After the applicant lowered the budget to $50,000, ReAct completed the checks and excluded MSAII for `TUITION_EXCEEDS_BUDGET`. All 14 oracle checks passed. The retest used seven requests, 92,074 input tokens and 6,648 output tokens with 26.67 seconds of service time. The estimated total cost was USD 0.08436990. Its manifest, traces, ledger, and summary are in `work/model-react-retest-01/`.

For main benchmark planning, the 630 formal fixture executions contained 1,804 model-shaped calls. Applying the mean cost per strategy and call purpose from the successful development attempts and the ReAct retest gives USD 20.86 at the observed caching rates and USD 28.37 when all input tokens are priced as uncached. The same two development cases per strategy project roughly 2.2 hours of serial service time. This small-sample projection covers the main benchmark and uses the pinned prices. Actual requests, pruning, replans, and cache hits can change the result.
