Date: 2026-11-17 (America/Los_Angeles). Branch: `homework/eval-harness-50`. H2 is complete. Main remains at `6ae734828c160b6f1fee5d3088b1b52b5f0b3ba9`; the public Streamlit app continues to use main.

## Delivered behavior

The CLI runs a native function-calling Agent or a non-agentic classic RAG adapter on a candidate-only input. Four read-only tools expose the same frozen catalog: exact program search, complete program lookup, verified source snapshot lookup and current-profile constraint checks. The Agent chooses an actual native function call or final answer after each observation. The baseline always executes search, scoped document retrieval, deterministic checks and one answer call per user turn. Its operations are labelled `fixed_pipeline`, never fabricated model-selected actions. This is a homework QA adapter around the production catalog, constraints, tuition calculations and output validator; the existing production service and website were not changed.

Each task execution starts fresh with an isolated profile, cache, conversation, call budgets and trace ID. Explicit profile changes pass through the same validated atomic patch path for both strategies; changed profiles invalidate cached checks. Earlier setup messages execute as actual turns and share the task budget. Ambiguous tuition/living-cost budgets receive a clarification without guessing a new tuition allocation.

Caps are eight model calls, twelve logical tool calls, 120 seconds per whole task, 45 seconds per model request and 1,800 output tokens per call; SDK retries are disabled. A third identical tool action stops the task. Cache hits still count as logical tool calls and are visible in traces. Missing sources, invalid arguments and stale profile versions are recoverable observations. Exhaustion, invalid output and provider errors remain saved terminal outcomes.

Spans record parent IDs, start/end/duration, observable inputs, selected actions, returned observations or structured failures, model version and actual usage when available. Developer prompts are versioned in code; the run records their combined candidate-code hash. Traces do not contain private model reasoning, credentials or evaluator references. Calls disabled by default produce an honest `model_disabled` outcome rather than a simulated answer.

## Reproduce

From the repository root, on the homework branch:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m scripts.homework.validate_tasks
.\.venv\Scripts\python.exe -m scripts.homework.run_task --strategy react --task-id d01
```

The final command intentionally makes zero API requests and saves a `model_disabled` record with exit code 1. Add `--live-model` to explicitly run a metered development task.
