Plan scopes and typed tool arguments support the full pool.
- The decision context and ranking input include reported English-test policies, GRE, application rounds and source dates. A separate structured `suggestions` field selects up to eight preliminary recommendations from code-generated allowed IDs. The validator checks retrieval, current screening, duplicate IDs and reason references. Names, links, dates, requirement summaries and recommendation explanations come from application data, not model-authored facts.
- The current assessment displays these as recommendations with a preliminary basis, including selected checks, application portal, reported rounds and CS Grad source/date. Unknown GPA, full-program tuition, course preparation and personal admission-tier evidence stay unknown. The unchanged formal recommendation field remains available for the separately supported Lottery/Reach/Target/Safer claims.
- With paid model calls disabled, the same Generate workflow offers explicitly labelled deterministic recommendations. It does not claim an adaptive model run. **Reviewed official records only** remains available for the original restricted workflow; CLI defaults and earlier milestone verifiers keep that scope unless `--recommendation-scope broad` is supplied.

## Screening boundaries

Applicable reviewed checks take precedence. A verified hard failure blocks preliminary selection. Where reviewed English is incomplete, an explicitly reported overall minimum can flag a below-floor selected-test score; being at or above it establishes only that numerical comparison, with subscores, age, waivers and other conditions pending. Recommendations, typical scores and subscores-only claims do not become overall hard minima. TOEFL versions are not converted, mismatched test dates remain pending, and tracker rules are not carried into a different intake.

Upcoming application rounds retain their actual labels/audiences. Cutoff time remains unverified on the listed date itself. A passed priority or scholarship date alone does not establish closure; all relevant listed rounds must be past, with an explicit final/only marker and no conflict, before the preliminary checker flags reported closure. Halt and doctoral-route flags are separate screening reasons. These remain reported or scope-based findings, not invented university decisions. Application fees retain unknown currency and are never tuition.

Budget/score follow-ups recompute the 83-record pool with current profile/evidence versions. Preliminary results are included in prior-reference resolution, session export and change tracking. Changing recommendation scope starts a fresh task while retaining the private profile. Hot-update handling preserves Session and provider classes and upgrades stale engine imports once.

The community context has its own semantic data hash, and the result records a combined recommendation-data hash over the program/source data and that community hash. A changed community context starts a fresh task instead of reusing old screening. Ranking input omits repeated unknown policy objects, unused historical source records and irrelevant test versions; displayed requirements and final screening still use the complete data. The controlled ranking payload fell from 444,838 to 242,813 characters before the final hash metadata was added. This is a payload-size comparison, not a measured token, latency or quality benchmark.
