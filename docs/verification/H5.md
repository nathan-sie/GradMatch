## Development before freezing

| Actual development revision | Executed | Passed | Failed | Judge errors | Estimated cost |

| Pilot 03, final revision | 32 | 30 | 2 | 0 | USD 0.25732890 |

Pilot 01 stopped after four executions of a 32-entry development plan; the other 28 entries remain unexecuted and are excluded from formal results. Pilot 02's failures/errors and all Pilot 03 outputs are retained. None of these development outcomes enters the 50-task formal scores.

The pilot exposed protocol problems before formal execution:

1. The Agent sometimes guessed an internal source ID and asked the user to resolve it. General tool instructions now distinguish program IDs from opaque source IDs and direct resolution through available catalog tools.
2. An interpreter sometimes wrapped a literal user substring in quotation marks. The homework patch path removes one matching wrapper only when its inner text is an exact user-message substring; the existing value/cue checks and atomic update remain in force. Normalization is recorded.
3. Free-written judge quotes could omit Markdown, paraphrase, or copy reference wording. Grader v2 retained presentation normalization, but full development still found fabricated quote strings. Grader v3 now requires a strict criterion object and evidence IDs selected from exact candidate-only spans. Code copies the chosen original substring. The semantic pass criteria did not change.

Both v2 and v3 were actually recalibrated using the same six authored examples and two saved H2 answers: eight judge requests per revision. Both agreed with all five original binary user labels; D remains skipped. These are five labels, not a 50-answer review. An old saved H2 answer received different semantic judgments across revisions; all judgments are retained rather than choosing the most favorable one.
