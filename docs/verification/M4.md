On November 19 the user supplied the exported session and confirmed that the budget update removed the project. The record identifies ReAct in snapshot mode. Profile v2 had one formal Lottery recommendation, CMU MSAII, with a published-rate tuition upper estimate of USD 137,400. At v3 the budget is USD 100,000, MSAII is excluded with `TUITION_EXCEEDS_BUDGET`, and there are no formal recommendations. Only the budget field changed; the other background fields still match the synthetic example. Both turns share one task, with counters accumulating to five model requests and two user turns. Both final validations have zero errors.

The trace also revealed an orchestration gap: on the budget turn the model chose `finish` using stale context, and the final deterministic validator performed the correct exclusion without a fresh ranking. The displayed removal was safe, but this could unnecessarily discard a still-supported recommendation after another budget change. The fix filters old profile-dependent checks/rankings/assistant summaries out of decision context, exposes current version-validity flags, and rejects finish or draft-free model validation until current checks and ranking have run. A successful empty search, explicitly labelled offline checks and reserved budget-final validation remain supported. Rejected finish actions consume no registered-tool unit; their model decision still counts.

Two new offline regressions reproduce premature finish and attempted draft-free validation: USD 139,000 retains supported MSAII; USD 100,000 excludes it. They also verify profile preservation, current versions, same-task cumulative budgets and final validation. All **146 checks**, including **38 M4 checks**, pass. No additional model request was made for this review/fix. The original manual-session outcome was not edited or presented as a rerun of the patched code.
