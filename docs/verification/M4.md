Two stopped after input interpretation; the third trace explicitly shows catalog-fact questions being marked as applicant ambiguity, while the first predates the added diagnostic output. One run exceeded its service-time limit during an execution-environment interruption. Its recorded elapsed time and billed response are retained rather than discarded. The shared input boundary now treats explicit read-only queries as nonmutating and defers catalog ambiguity to tools.

A later action response contained two identical JSON objects. The original strict single-object parser rejected it and recorded the paid failure. After adding diagnostics, this protocol behavior was observed again. The adapter now normalizes only identical objects; differing objects, duplicate keys or trailing garbage still fail. No arbitrary first-answer extraction or paid automatic retry is used.
